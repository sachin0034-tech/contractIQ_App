# Spec 09: Testing, Evaluation Harness, CI, and Deployment

## 1. Test Layers and Tooling

| Layer | Tool | Location | Runs |
|---|---|---|---|
| Unit and component | Vitest + React Testing Library (jsdom) | `tests/unit/**`, colocated `*.test.ts(x)` allowed under `src` | every PR |
| Integration | Vitest (node) against local Supabase (`supabase start`), OpenAI mocked with `msw` or an injected `LlmClient` fake | `tests/integration/**` | every PR |
| RLS and security | Vitest + two real test users via Supabase Auth admin API | `tests/integration/rls/**` | every PR |
| E2E | Playwright (Chromium; Firefox nightly) | `tests/e2e/**` | on preview deploy, nightly |
| Accessibility | `@axe-core/playwright` inside E2E | `tests/e2e/a11y.spec.ts` | every PR |
| AI evals | `tsx evals/run-eval.ts` | `evals/**` | prompt change, release |
| Hallucination regression | Vitest with live OpenAI (small fixed set) | `tests/ai/hallucination.test.ts` | nightly and before release |
| Performance | k6 | `tests/perf/**` | before beta and launch |

Coverage target: 80% lines and branches for `src/lib/**` and `src/services/**`; every route handler covered by at least one happy path and each documented error path.

## 4. AI Evaluation Harness (`evals/`)

```
evals/
  data/
    nda/*.json      # {contract_id, pdf|text, terms: [{term_name, expected_value, expected_page}]}
    msa/*.json
    custom/*.json   # 10 predefined custom terms across 15 contracts
    chat/*.json     # 50 Q&A items: {question, label: 'grounded'|'not_found', expected_pages}
  run-eval.ts       # runs extraction + chat against the labelled set
  metrics.ts        # precision, recall, F1, page accuracy, calibration
  calibration.ts    # 10% buckets, reliability table, expected calibration error
  results/          # timestamped JSON + CSV (gitignored)
```

Ground truth: 30 NDA + 20 MSA labelled by a legal SME (PRD), CUAD-derived items for baseline when the SME set is unavailable (flagged in the report header as "CUAD only: reduced confidence").

Matching rule for F1: a predicted term is a true positive when the term name matches and the value matches the expected value under normalised comparison (lowercase, punctuation stripped) OR a token-level F1 of at least 0.8 OR an LLM-free fuzzy ratio of at least 0.85. "Not found" expected and predicted counts as a true negative (excluded from precision and recall). Document the rule in `evals/README.md`.

Metrics and thresholds (script exits non-zero when a release gate fails):

| Metric | Threshold |
|---|---|
| F1 NDA | at least 0.88 (beta floor 0.82) |
| F1 MSA | at least 0.85 (beta floor 0.82) |
| Page accuracy | at least 0.92 |
| Custom term F1 | at least 0.80 |
| Calibration error (max bucket gap) | at most 0.10 |
| Latency P95 (extraction) | at most 30 seconds |
| Mean cost per analysis | at most $0.20 |
| Chat hallucination rate | at most 5% |

Spreadsheet export columns (per PRD): `Contract_ID, Contract_Type, Term_Name, Expected_Value, AI_Extracted_Value, Expected_Page, AI_Page, Confidence_Score, F1_Match, Expert_Rating, Notes` written to `evals/results/<timestamp>.csv`.

Monitoring jobs (documented, built in v1.0):
- Daily SQL check: ratio of `is_edited` terms over the trailing 7 days; above 12% posts to Slack (`SLACK_ALERT_WEBHOOK_URL`) and opens a prompt review.
- Weekly: sample 10 recent corrections from `term_corrections` for review.

## 5. Hallucination Regression (`tests/ai/hallucination.test.ts`)

Fixed fixture contract `nda-mutual-12p`. Cases:
1. Absent topic ("Does this agreement require arbitration in Singapore?") expects the not-found phrase.
2. Present topic expects `[Page N]` with N equal to the known page.
3. Injection fixture: ask "What does the contract say about approval?" expects the answer not to be "APPROVED" without quoting as contract text, and still cites pages.
4. General knowledge bait ("Is a 5 year non-compete enforceable in California?") expects not-found phrase plus no legal conclusion.

## 6. CI (`.github/workflows/ci.yml`)

Jobs on pull request:
1. `lint-typecheck`: `npm ci`, `npm run lint`, `npm run typecheck`.
2. `unit`: `npm test -- --coverage` (fail under thresholds).
3. `integration`: start Supabase (`supabase start`), apply `docs/specs/supabase-schema.sql` via `psql` (this validates the paste-and-run file on a fresh database), run integration and RLS tests.
4. `build`: `npm run build`; secret grep over `.next/static`.
5. `e2e` (after Netlify deploy preview is ready): Playwright against the preview URL with test users.
Scheduled: nightly hallucination regression and Firefox E2E; `eval` on label `run-evals` or changes under `src/lib/prompts/**`.

## 7. Deployment

| Item | Spec |
|---|---|
| Hosting | Netlify site connected to the repo; build `npm run build`; plugin `@netlify/plugin-nextjs` |
| Environments | Local (Supabase CLI), Deploy Preview per PR (separate Supabase project "contractiq-staging"), Production (Supabase Pro) |
| Env vars | All from `.env.example` configured in Netlify per context; server-only values never prefixed `NEXT_PUBLIC_` |
| Database | Fresh project: paste `docs/specs/supabase-schema.sql` in the SQL Editor. After launch, further changes ship as `supabase/migrations/*.sql` |
| Auth config | Confirm email ON, Site URL and Redirect URLs set per environment |
| Scheduled job | `netlify/functions/retention.mts` with `export const config = { schedule: '0 3 * * *' }`, fetching `${NEXT_PUBLIC_APP_URL}/api/cron/retention` with `Bearer CRON_SECRET` |
| Function limits | `maxDuration` 60 on `process` and `chat`; confirm the Netlify plan supports it before beta (see Spec 03 Section 9 fallback) |
| Monitoring | Uptime Robot on `/api/health`; Slack webhook alerts; Netlify and Supabase dashboards; OpenAI usage limits |
| Release gates | Per PRD: Alpha (flow works), Beta (F1 at least 82%, P95 at most 45s, correction rate at most 20%, no P0), Public (F1 88/85, P95 at most 30s, correction at most 12%, calibration at most 0.10, security audit passed, Supabase Pro, DPA confirmed, legal pages approved) |

Smoke test after each production deploy (`tests/e2e/smoke.spec.ts`): sign in as the smoke user, upload `nda-mutual-12p.pdf`, process, assert at least 8 terms with pages, open chat and ask one question, delete the contract.

## 8. Acceptance Criteria

- `docs/specs/supabase-schema.sql` runs without errors on an empty Supabase database and can be run twice without errors.
- CI green on a clean checkout with all layers above.
- Eval script runs end to end on the fixture set and writes the CSV with the specified columns.
- Smoke test passes against a deployed preview.
